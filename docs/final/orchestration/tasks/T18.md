## What to build

1. The landing state of `online.html` offers **Create room** and **Join room** (a 4-letter code field). Style it to match the existing page.
2. Create: the server makes a new room with one `Match`, returns a 4-letter code (uppercase A–Z, no I and no O; generated from a server-owned `random.SystemRandom` or `secrets`, never from the duel seed), and the creator takes seat A. The code is shown on the page so it can be read aloud.
3. Join: the code is matched case-insensitively; the joiner takes seat B. An unknown, full or expired code gets a clear message ("No room with that code", "That room is full"), and nothing else about other rooms leaks (no list of rooms, no count, no timing difference that matters).
4. Several rooms run at once, each with its own `Match`, tick loop, seed handling, pause/forfeit (#38, #48), rematch (#41, #46) and trace file (the trace name includes the code). A stall in one room never delays another (T13-QA-1 still holds per room).
5. Seat tokens (reconnect, the "replaced" close) are per room; a token from room X never rejoins room Y.
6. A room expires when both seats have been gone past the forfeit window, or 10 minutes after creation with no second player. Its code may be reused only after it expires.
7. `--rival baseline` (human vs the baseline on seat B): Create gives a room where seat B is the AI at once; Join is not needed. Keep `--neutral`.
8. Brute-force guard: at most 10 failed joins per connection per minute (then a short refusal). Document the number as a proposal for Saad.
9. Update `docs/final/ONLINE_PLAY.md` (how to play with a code) and the key hints only as far as the page flow needs. Do not change the key mapping: that is T19.

## Rules that still hold

The server owns the only `GameState` per room; clients send only `join`/`create`, held keys and `rematch`; each client receives only its own seat's observation (AGENTS.md "Online play"). No room's data goes to another room's client.

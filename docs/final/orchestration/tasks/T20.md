## What to build

1. `python -m server --playtest [--telemetry-dir traces/playtest]` and `play.py --versus --playtest`: off by default. With the flag, one JSON Lines file per room, duel and seat: `traces/playtest/<date>-<room>-<duel n>-<seat>.jsonl` (gitignored). The first line is a header: build commit, config versions, seed (host-only file), rival kind, seat, room code; no names, IPs, user agents or tokens.
2. Events (#68), each `{"t": tick, "s": seconds since duel start, "seat": ..., "type": ..., ...}`: `duel_start`, `action` (resolved action, accepted or refused, effect), `room` (entered room id), `disguise_on`, `disguise_broken` (cause), `sword_drop`, `sword_pickup`, `trap_rigged`, `trap_sprung` (whose trap, for the owner's log only), `hit`, `heart_lost`, `idle` (start and end of a spell with no accepted action for at least 3 s; the threshold is a named constant, a proposal for Saad), `pause`, `disconnect`, `reconnect`, `forfeit`, `duel_end` (outcome, reason), `rematch` (pressed, or not pressed before the room closed).
3. Each seat's log holds only facts that seat's own observation could show, plus its own actions; nothing about the other seat that its observation hides (disguise identity, the other's trap ownership). A combined host-side summary per duel is allowed.
4. Telemetry never touches the engine RNG or `GameState`: the duel trace and state hash are the same with and without `--playtest`. Wall-clock seconds come from the server's clock, outside the engine.
5. `tools/telemetry/summarize.py`: reads a directory of logs and writes a JSON + Markdown summary per seat and per duel: stalls (idle spells, runs of refused actions, time stuck in one room), quits (disconnect, forfeit, no rematch, duel abandoned), and mechanics never used or used once (TAKE, RIG, flip, block, draw/sheathe, sword pickup). Deterministic output for the same input. This is the tool the T21 analyst runs.
6. `docs/final/playtest/TELEMETRY.md`: how to turn it on, what is recorded and what is not, the file format. A draft sentence for `CONSENT.md` "What is recorded", marked "draft for Saad's approval" (do not change the rest of that file).

## Acceptance (failing tests first)

1. Off by default: no file written without the flag.
2. With the flag, a scripted two-client duel writes both seats' logs with the event types above, in tick order.
3. Leak test: a disguised rival's identity and the other seat's trap ownership never appear in a seat's log.
4. The duel trace and state hash are identical with and without `--playtest`.
5. No client message changes with the flag on (same payloads as without).
6. `summarize.py` on a fixture directory gives the expected stalls, quits and unused mechanics; output is byte-identical on two runs.
7. Suite green, with the real line pasted.

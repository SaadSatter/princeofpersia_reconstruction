Design:
1. `web/bridge.py` (importable under CPython and Pyodide, standard library only): `WebGame(mode="human_vs_ai"|"local_two_players", seed, human_seat="A", rival=...)`, `press(keys: dict)` -> per-seat input using the same key map as `play.py --versus`, `tick()` -> JSON-serialisable payload `{"seat_view": observe(human_seat), "draw": [...], "hud": {...}, "outcome": ...}`. In local_two_players mode a payload is produced per seat and the page shows two panels, as the local bench does (label this mode as a local test mode: both players see both panels).
2. A pygame-free `render/draw_list.py` (or similar) that turns one seat's observation into a list of sprite draws (sheet, frame, x, y, flip, layer) and HUD items, reusing the existing pose and animation helpers, so Phaser only blits. Every value comes from that seat's observation.
3. `web/index.html`, `web/main.js`: load Pyodide, unpack the game archive, start `WebGame`, run at 12 ticks per second, map keys, draw with Phaser, show the outcome and a rematch key. No game logic in JS.
4. `tools/web/build.py`: writes `web/dist/` (index.html, main.js, `game.zip` of the needed Python packages, the sprite sheets and a manifest). It is reproducible: the same inputs give the same output, and the hashes are printed. `web/dist/` is gitignored; Pages deploys from the build step.
5. `.github/workflows/pages.yml` (build, then deploy to GitHub Pages on push to main) and `.github/workflows/web-smoke.yml` (on PR: build, serve, Playwright in Chromium loads the page, waits for "ready", holds a key for 2 s, asserts the frame counter advanced and no console errors, saves a screenshot artifact). Read-only token; no secrets.
6. `docs/final/WEB_BUILD.md`: how to build, run locally (`python3 -m http.server` in `web/dist`), deploy, the pinned versions, and the static-page knowledge-boundary limitation (devtools can read state; fine for human vs AI and local play; online human vs human needs a server, deferred).

3. The key map matches `play.py --versus` (test against its table, imported or parsed).
4. `tools/web/build.py` runs in the sandbox and produces a manifest with stable hashes across two runs.
5. JS: `node --check web/main.js` passes; a Node unit test of any pure JS helpers (key mapping, interpolation), if there are any.

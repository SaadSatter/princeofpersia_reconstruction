## Goal

The server holds the only `GameState` and steps it 12 times a second. Each browser sends only the keys its player holds. Each browser receives only its own seat's payload and draws it.

## What to build

1. **`server/` package** (new), runnable as `python -m server [--host 0.0.0.0] [--port N] [--seed N] [--rival baseline]`. On start it prints the LAN URL.
   - One duel at a time (GDD: no matchmaking, no accounts). The first browser to join gets seat A and the second gets seat B. A third gets a "full" message and is closed.
   - Each joiner gets an unguessable **seat token** (`secrets`), so it can reconnect to the same seat. A token is never sent to the other seat.
   - `--rival baseline`: the server plays seat B with `agents/versus_baseline.py`, through the same per-seat observation, so one human can test alone. Label the rival as in the web build. Optional; build it after items 1–5 work.
2. **Authority and inputs.**
   - A client message carries only the set of key names its player holds, from its seat's key map. The server turns them into that seat's input with the same logic as `web/bridge.py` (`seat_input`, the in-air LUNGE → KICK swap, filtered by `legal_actions(seat)`). Reuse that code; do not copy it.
   - The server ignores unknown keys, malformed JSON, oversize messages and messages that claim another seat, and never crashes on them.
   - Clients never send outcomes, positions or actions.
3. **What a client receives: its own seat only.** Each tick a client receives that seat's payload, the same shape as `WebGame._seat_payload` (`seat_view`, `draw`, `hud`, `outcome`), built from `observe(seat)` alone. **Never** send the `GameState`, the other seat's observation, payload, keys, token, input counts or connection details, the seed, the arena layout beyond that seat's view, trap ownership, the guards' scripts, or whether the other figure is a disguised rival.
   - The payload must be identical whether a guard-looking figure is a real guard or the disguised rival (R-V25).
   - Error and status messages must not differ by hidden state either.
4. **Clock and determinism.**
   - The server loop paces 12 ticks per second with an injectable clock. Wall time is used only for pacing, never inside the engine.
   - Each tick applies the latest held-key set per seat; a seat with no message holds nothing.
   - The server writes a per-tick input trace (both seats' resolved inputs, seed). Replaying it through `VersusEpisode` gives the identical outcome and state hash. This trace stays on the server and is never sent to a client.
5. **Disconnect (#38) and rematch (#25).**
   - When a seat's socket drops mid-duel, the duel pauses for both players, and each client is told only "Rival disconnected, waiting up to 15 s" or "Reconnecting".
   - If that seat's token reconnects within 15 s, play resumes; otherwise the disconnected seat loses. The end screen says "Rival disconnected" or "You disconnected".
   - This is a server rule. Add a `docs/RULE_SOURCE_MAP.md` row labelled `design` (decision #38), with a failing test first. Do not change `pop/`: pausing means the server does not tick.
   - **Rematch (#41).** When the duel ends, a **Rematch** button pops up on each player's screen in the game's own style. It is drawn in Phaser or CSS from the existing generated dungeon art and palette (`assets/generated/`, `docs/final/ART_PROVENANCE.md`): pixel-art edges, no smoothing, no stock web widget look. Do not generate or add new art assets.
     - Pressing it (click, or a key such as R or Enter, shown on the button) sends a rematch request. The new duel starts with the same seed (#25) once **both** players have pressed. Until then the presser sees "Waiting for rival…".
     - Use the same button in the human-vs-AI and local web modes (there, one press restarts).
     - The request is an intent, like keys. The server decides. Whether the other player pressed is shown only as "Rival wants a rematch", which reveals no hidden state.
6. **Browser client: an online mode in `web/`.**
   - Online mode does not load Pyodide or `game.zip`. It connects by WebSocket to the same origin, sends held keys on change, and draws the payload with the existing Phaser drawer.
   - It shows status (connecting, waiting for rival, paused, ended), the seat's key hints and the build hash.
   - It contains no game logic (extend `tests/test_web_js.py` or add a test).
   - The server serves the page and the art over HTTP on the same port, or on a second documented port.
   - Phaser still comes from the pinned CDN (#25), so the laptop and the players need internet. Say so in the docs.

## Acceptance criteria (failing tests first, committed before the implementation)

1. **Two clients, one duel.** A localhost test runs the server in-process, with an injected clock, and connects two WebSocket clients. Both get distinct seats; their key messages move their own rival and never the other; a third client gets "full".
2. **Boundary.**
   - A test records every message sent to client A over a duel in which B disguises and rigs a trap. No message contains B's observation, B's token, the seed, trap ownership, a `disguised` flag or identity of another figure, or any key outside an allow-list of payload fields.
   - A real-guard and a disguised-rival setup in the same spot give byte-identical messages to the watching client.
   - Status messages are the same for every hidden state.
3. **Authority.** Malformed, unknown, oversized and other-seat messages are ignored without a crash, and illegal inputs are filtered by `legal_actions`. A client cannot end the duel or move the other seat.
4. **Determinism.** Replaying the server's input trace through `VersusEpisode` reproduces the outcome and final state hash.
5. **Disconnect (#38).** With a fake clock:
   - a drop pauses both seats (no ticks);
   - a reconnect with the token within 15 s resumes from the same frame;
   - with no reconnect the disconnected seat loses, with a reason the end screen shows;
   - a wrong token cannot take a seat.
6. **Rematch (#41).** The button appears only after the duel ends. Both presses restart the duel with the same seed (#25); one press shows "Waiting for rival…". In single-human modes one press restarts. A test also checks that the page code draws the button with the game's art or palette (no default browser button styling); the visual check itself is for QA or Saad.
7. **No websockets import** in `pop/`, `agents/`, `render/`, `play.py` or `web/bridge.py`. `uv lock --check` passes, and the lock diff adds only websockets (and its dependencies, if any).
8. **Suite:** `uv run --extra online --extra train pytest -q`. Paste the real line and name every failure (expected: only the pre-existing T07 fixture test).
9. **Manual run (if you can):** start the server and open two clients (a browser, or scripted WebSocket clients). Say exactly what you ran, and what you could not run.
